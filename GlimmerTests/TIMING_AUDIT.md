# Test timing and shared-state audit

Scope: `GlimmerTests`, reviewed on 2026-10-12. Direct delay, clock and singleton
references were searched, along with the production timers exercised by the
changed tests. This is a source audit, not proof that every transitive
dependency is isolated. The scheme currently disables parallel testing;
suite-local serialization alone would not protect globals if cross-suite
concurrency is enabled.

Additional indirect risks found while tracing the fixtures:

- `TelemetryCaptureTests`, `TelemetryConfigRowTests` and other exporter fixtures
  reach static `TelemetryExporter.captureBaselines` and shared receive-timing
  collectors; suite-local serialization does not isolate these across suites.
- `AudioEngineLifecycleTests.rawListenerFired` is a static semaphore; a late
  signal can survive into a later iteration.
- Decoder, audio and input fixtures can write `TelemetryCounters.shared` even
  when the test does not name it; this can contaminate the exact counter-delta
  assertions listed above.
- Frame-pacer fixtures that reconcile real deficit timers
  (`FramePacerTickTests`, `FramePacerDeficitEventTests`) retain real timer
  delivery even when their decision timestamps are scripted.
